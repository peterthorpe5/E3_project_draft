E3 PROJECT DRAFT: STAGE 07 RECOVERY SOURCE PACKAGE
==================================================

Release: 0.9.1
Prepared: 27 July 2026
Project: PT_E3_6 / ARIA plant E3

PURPOSE
-------

This complete source package repairs the high-memory Stage 07 Expression Atlas
execution path, detects stale installations such as e3-workflow 0.7.6 before a
run starts, and removes the accidental nested repository copy.

Unpacking the ZIP creates exactly one top-level directory:

    E3_project_draft/

INSTALL AND PROVE THE ACTIVE SOURCE
-----------------------------------

From the unpacked repository:

    cd E3_project_draft/e3_end_to_end_workflow

    conda run --name e3_end_to_end_workflow \
        python -m pip install \
        --no-deps \
        --force-reinstall \
        --editable "$(pwd)"

    conda run --name e3_end_to_end_workflow \
        e3-workflow diagnose-install \
        --source-root "$(pwd)" \
        --require-source-match

The diagnostic must report:

    status: MATCHED_SOURCE
    source_version: 0.9.1
    imported_version: 0.9.1

SAFE RECOVERY OF THE 24 JULY RUN
--------------------------------

Do not delete the valid Stage 00 through Stage 05 directories. Resume the same
immutable configuration through the Slurm controller:

    cd E3_project_draft

    ./run_e3_pipeline.sh \
        --mode slurm \
        --config /gpfs/uod-scale-01/cluster/gjb_lab/pthorpe001/2026_E3_protac/E3_project_draft/e3_end_to_end_workflow/config/grant_aligned_reuse_q9sa03_only_v0_7_3_20260724.cluster.yaml \
        --max-jobs 4 \
        --account barton \
        --partition general \
        --resume

Do not add --stop-after when the intention is to complete the whole enabled
workflow.

RECOVER THE PREVIOUS SCHEDULER EVIDENCE
---------------------------------------

The retained Stage 07 log contains only Snakemake's generic job-failed summary.
It does not prove whether Slurm killed the process for memory. Locate the child
job around 24 July 2026 13:32 and inspect it:

    sacct -u "${USER}" \
        --starttime 2026-07-24T13:20:00 \
        --endtime 2026-07-24T15:30:00 \
        --format=JobIDRaw,JobName,State,ExitCode,Elapsed,ReqMem,MaxRSS,NodeList,Reason \
        --parsable2

Then rerun sacct with --jobs JOB_ID for the relevant child and batch steps.

WHAT STAGE 07 NOW DOES
----------------------

    * validates the complete Expression Atlas resource manifest and checksums;
    * scans data partitions only for selected group-member species;
    * reduces Atlas measurements to candidate genes before alias expansion;
    * limits DuckDB managed memory to 75% of the stage request and enables spill;
    * materialises mapping and summary tables once; and
    * records partition and memory controls in expression_validation.tsv.

The strict missing-evidence and ambiguous-identifier rules are unchanged.
