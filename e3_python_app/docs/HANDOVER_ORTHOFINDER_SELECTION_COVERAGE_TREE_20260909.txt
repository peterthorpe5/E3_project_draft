2. USER REQUEST
---------------

Provide a phylogenetic/taxonomic visualisation that helps users construct and
understand combined selections. It must show:

  - selected exact taxa;
  - included clades;
  - only-in-clade scope;
  - excluded exact taxa and excluded clades;
  - taxa represented by the loaded OrthoFinder input;
  - represented hits outside an included-clade search scope;
  - reviewed expected taxa that have no data;
  - input labels lacking a reviewed taxonomy mapping.

Example selection:
  Include Poaceae, exclude exact Solanum tuberosum, permit members elsewhere.

The figure is a selection and coverage aid. It is not a gene tree, is not a HOG
phylogram and must not imply biological absence when a taxon has no sampled data.

3. DEFINITIONS THAT MUST REMAIN SEPARATE
----------------------------------------

Species/taxonomy coverage tree
  A pruned hierarchy of reviewed taxonomic lineages for input or expected taxa.
  This is the feature requested here.

Species tree
  The topology used or inferred by OrthoFinder. It may differ in detail from an
  NCBI taxonomy tree. If shown, label its authority explicitly.

Gene tree or HOG phylogram
  Evolutionary relationships among genes within a HOG. Existing group-tree
  functionality must remain separate.

Represented
  At least one exact input species label has a reviewed mapping to the taxon.

No data
  A taxon is in a declared, reviewed expected-taxon universe but no corresponding
  input label is represented. This means “not represented in this dataset”, not
  “the gene/HOG is biologically absent”.

Unmapped
  An input source label lacks a reviewed exact mapping. It must never be placed
  speculatively on the tree.

4. SELECTION SEMANTICS
----------------------

All active selectors compose with logical AND. Preserve these exact meanings:

Required exact taxon
  Every selected terminal taxon must occur in the group.

Include clade
  Every selected clade must contribute at least one group member. Members from
  outside the selected clade are allowed and must be counted/reported.

Only in clade
  At least one member must fall within the selected clade and no member may occur
  outside it. Unmapped members make an only-in result fail closed because their
  lineage cannot be proven inside the allowed scope.

Exclude exact taxon
  No member may have the selected terminal taxon ID.

Exclude clade
  No member may descend from the selected clade.

When several only-in clades are selected, use the intersection of their mapped
member sets, matching the current E3 selector behaviour. If the product owner
wants union semantics later, expose it as a separately named mode; never change
the meaning silently.

Reject contradictory predicates before query execution, including:
  - the same exact taxon required and excluded;
  - an included clade fully covered by exclusions;
  - a required exact taxon outside the only-in scope;
  - only-in clades with no represented intersection;
  - unknown taxon IDs under the chosen authority.

6. TAXONOMY AUTHORITY AND INPUT CONTRACT
----------------------------------------

The renderer must be offline and deterministic. Do not query a live taxonomy
service every time the app redraws.

Consume a versioned reviewed taxonomy mapping with at least:
  workflow_species_label
  accepted_species_name
  ncbi_taxon_id
  lineage_taxon_ids
  lineage_names
  lineage_ranks
  taxon_rank
  mapping_status
  mapping_method
  mapping_reason
  taxonomy_authority
  taxonomy_release
  source_name_original

`lineage_*` values are ordered root-to-terminal semicolon-delimited vectors and
must have equal length. Only `mapping_status=REVIEWED` enters the authoritative
tree. Retain pending, ambiguous and unmapped input labels in a separate table.

Support terminal ranks including:
  species
  subspecies
  varietas
  forma
  cultivar where the chosen authority supplies a stable reviewed identifier

Do not invent an NCBI taxon ID for a cultivar not represented by NCBI Taxonomy.
If the project uses an additional controlled cultivar authority, preserve both
`taxonomy_authority` and the authority-specific ID; do not mislabel a project ID
as an NCBI taxon ID.

The expected-taxon universe must be explicit. Valid sources include:
  - a reviewed project sampling manifest;
  - the exact species list supplied to an OrthoFinder run;
  - a user-selected reviewed target list;
  - a bounded descendant list from a pinned taxonomy release.

Never expand “all descendants of Eukaryota” by default. Large clades require a
reviewed bounded universe or an explicit maximum and warning.

8. TREE CONSTRUCTION ALGORITHM
------------------------------

1. Validate the taxonomy release and reviewed mapping.
2. Resolve selection taxon IDs only against that authority.
3. Define the displayed terminal universe as the union of:
     represented reviewed input taxa;
     declared expected taxa;
     exact selected/excluded taxa;
     reviewed terminals needed to explain active clade selectors.
4. Add every ancestor required to connect those terminals to their least common
   displayed root.
5. Preserve original parent relationships and lineage depth.
6. Collapse unary neutral internal nodes only when the user enables a labelled
   compact mode. Never collapse a selected/excluded node.
7. Attach selection and coverage attributes independently.
8. Calculate descendant counts for represented, expected-no-data and excluded
   terminals.
9. Produce stable child ordering: lineage order/name/taxon ID with explicit
   deterministic rules.
10. Reconcile displayed leaves and counts against the source manifests before
    rendering.

If the OrthoFinder species-tree topology is offered as an alternative, label the
view “OrthoFinder species tree” and keep taxonomy-lineage selection semantics
available. Do not silently mix edges from two authorities.

15. CLUSTER AND MAC PATH RULES
------------------------------

The Mac workflow must not require /tmp.

On the cluster, stage temporary computation under the scheduler-provided TMPDIR
and copy validated results to a persistent working directory. Do not hard-code
/tmp and do not use destructive rsync options.

Example cluster pattern:

  set -Eeuo pipefail
  : "${TMPDIR:?The cluster must provide TMPDIR}"
  PERSISTENT_OUTPUT="/persistent/path/orthofinder_selection_coverage"
  JOB_TOKEN="${SLURM_JOB_ID:-manual}"
  JOB_WORK_DIR="${TMPDIR}/orthofinder_coverage_${JOB_TOKEN}"

  mkdir -p "${JOB_WORK_DIR}" "${PERSISTENT_OUTPUT}"
  rsync -a "/persistent/path/Results_example/" \
    "${JOB_WORK_DIR}/Results_example/"

  orthofinder-results coverage-tree \
    --results-dir "${JOB_WORK_DIR}/Results_example" \
    --taxonomy-map "/persistent/path/reviewed_taxonomy_mapping.tsv" \
    --expected-taxa "/persistent/path/expected_taxa.tsv" \
    --output-dir "${JOB_WORK_DIR}/published"

  rsync -a "${JOB_WORK_DIR}/published/" "${PERSISTENT_OUTPUT}/"
